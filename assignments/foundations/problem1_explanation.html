1a — Minimizing a Weighted Quadratic

Find the point θ that minimizes a weighted sum of squared distances.

Problem Setup

You have positions \(x_1, \dots, x_n\) on a number line and positive importance weights \(w_1, \dots, w_n\). Minimize:

$$f(\theta) = \frac{1}{2} \sum_{i=1}^{n} w_i \,(\theta - x_i)^2$$
Intuition

🏘️ The "Loud Friends on a Street" Analogy

Imagine \(n\) friends at positions \(x_1, \dots, x_n\). Each friend has a "loudness" \(w_i\) — the louder they are, the more they'll complain if you stand far away.

You want to stand at the spot \(\theta\) where total complaining is minimized. Naturally, you'd stand closer to the louder friends.

That's exactly a weighted average.

Step-by-Step Solution
1

Take the derivative of \(f(\theta)\) with respect to \(\theta\).

$$f'(\theta) = \frac{d}{d\theta}\left[\frac{1}{2}\sum_{i=1}^{n} w_i(\theta - x_i)^2\right]$$
Using the chain rule on each term:
$$f'(\theta) = \sum_{i=1}^{n} w_i\,(\theta - x_i)$$
2

Set the derivative to zero and solve for \(\theta\).

$$\sum_{i=1}^{n} w_i\,(\theta - x_i) = 0$$
Expand:
$$\theta \sum_{i=1}^{n} w_i \;-\; \sum_{i=1}^{n} w_i\, x_i = 0$$
Rearrange:
$$\theta \sum_{i=1}^{n} w_i = \sum_{i=1}^{n} w_i\, x_i$$
3

Confirm it's a minimum. The second derivative is \(f''(\theta) = \sum w_i > 0\), so the function is convex (bowl-shaped). ✅

$$\theta^* = \frac{\displaystyle\sum_{i=1}^{n} w_i\, x_i}{\displaystyle\sum_{i=1}^{n} w_i} \qquad \text{(the weighted average!)}$$
What if some \(w_i\) are negative?
⚠️The second derivative \(\sum w_i\) could become ≤ 0. The "bowl" flips into a "hill" — the critical point becomes a maximum, not a minimum.
💥If the total weight is negative, \(f(\theta) \to -\infty\) as \(|\theta| \to \infty\). No minimum exists.

1b — Sum of Max vs. Max of Sum

When you can optimize each piece individually vs. all at once, which is better?

Problem Setup
$$f(\mathbf{x}) = \sum_{i=1}^{d} \max_{s \in \{1,-1\}} s\, x_i$$
$$g(\mathbf{x}) = \max_{s \in \{1,-1\}} \sum_{i=1}^{d} s\, x_i$$

Which is always true: \(f \leq g\), \(f = g\), or \(f \geq g\)?

Intuition

🍽️ The "Restaurant" Analogy

🅰️\(f\): Each person picks their own favourite meal independently. Everyone is happy.
🅱️\(g\): The whole group must order the same meal. Some people won't get their favourite.

Individual choice is always at least as good as forced group choice!

Step-by-Step Proof
1

Simplify \(f\). For each coordinate, \(\max(x_i, -x_i) = |x_i|\).

$$f(\mathbf{x}) = \sum_{i=1}^{d} |x_i|$$
2

Simplify \(g\). One sign \(s\) for all coordinates:

$$g(\mathbf{x}) = \max\!\left(\sum_{i} x_i,\; -\sum_{i} x_i\right) = \left|\sum_{i=1}^{d} x_i\right|$$
3

Apply the Triangle Inequality:

$$\left|\sum_{i=1}^{d} x_i\right| \;\leq\; \sum_{i=1}^{d} |x_i|$$

This gives us \(g(\mathbf{x}) \leq f(\mathbf{x})\).

$$f(\mathbf{x}) \;\geq\; g(\mathbf{x}) \quad \text{for all } \mathbf{x}$$

Example: \(\mathbf{x} = (3, -1)\) → \(f = |3| + |-1| = 4\), \(g = |3 + (-1)| = 2\). Indeed \(4 \geq 2\). ✓

1c — Expected Points from a Dice Game

A recurrence approach to compute expected value — the same idea behind MDPs.

Problem Setup

Roll a fair 6-sided die repeatedly until you roll a 1 (then stop).

  • Roll a 2 → lose \(a\) points
  • Roll a 6 → win \(b\) points
  • Roll 3, 4, 5 → nothing happens

What is the expected total number of points when you stop?

Key Insight

Every time you haven't rolled a 1, the situation is exactly the same as when you started. So we can define:

$$V = \text{expected total points from this point forward}$$

…and write a self-referencing equation (recurrence) for \(V\).

Step-by-Step Solution
1

Build the recurrence. On each roll:

RollProb.PointsFuture
1\(\frac{1}{6}\)\(0\)Stop
2\(\frac{1}{6}\)\(-a\)Continue → add \(V\)
3\(\frac{1}{6}\)\(0\)Continue → add \(V\)
4\(\frac{1}{6}\)\(0\)Continue → add \(V\)
5\(\frac{1}{6}\)\(0\)Continue → add \(V\)
6\(\frac{1}{6}\)\(+b\)Continue → add \(V\)
2

Write the equation:

$$V = \frac{1}{6}(0) + \frac{1}{6}(-a + V) + \frac{1}{6}(V) + \frac{1}{6}(V) + \frac{1}{6}(V) + \frac{1}{6}(b + V)$$

Simplify the right side:

$$V = \frac{1}{6}\big(-a + b + 5V\big)$$
3

Solve for \(V\):

$$6V = -a + b + 5V$$
$$6V - 5V = b - a$$
$$V = b - a$$
$$V = b - a$$

Sanity checks:

✅\(a = 0, b = 0 \Rightarrow V = 0\). No points at stake — makes sense.
✅\(a = 0, b = 5 \Rightarrow V = 5\). Can only win — positive!
✅\(a = 3, b = 0 \Rightarrow V = -3\). Can only lose — negative.
Lecture Connection

This recurrence is a Bellman equation in disguise — the same technique used in Markov Decision Processes (MDPs) that you'll study later in the Blackjack assignment. The value \(V\) here is like a "state value" — the expected future reward from the current state.

1d — Maximum Likelihood for a Coin

What's the most likely bias of a coin given observed flips?

Problem Setup

A coin has probability \(p\) of heads. We flip it 7 times and observe: H, H, T, H, T, T, H (4 heads, 3 tails).

$$L(p) = p^4\,(1-p)^3$$

Find the \(p\) that maximizes \(L(p)\).

Intuition

🔍 The Detective Analogy

You're a detective. You see the evidence: 4 heads out of 7 flips. Your best guess for the coin's bias is simply the fraction of heads you saw:

$$p^* = \frac{4}{7} \approx 0.571$$

The math below proves this is exactly right.

Step-by-Step Solution
1

Take the logarithm. Since \(\log\) is monotonically increasing, the \(p\) that maximizes \(\log L(p)\) also maximizes \(L(p)\). But logs are much easier to differentiate (products become sums).

$$\log L(p) = 4\log p + 3\log(1-p)$$
2

Differentiate with respect to \(p\):

$$\frac{d}{dp}\log L(p) = \frac{4}{p} - \frac{3}{1-p}$$
3

Set the derivative to zero and solve:

$$\frac{4}{p} \;=\; \frac{3}{1-p}$$
Cross-multiply: multiply both sides by \(p(1-p)\):
$$4\,(1-p) \;=\; 3\,p$$
Expand the left side:
$$4 - 4p \;=\; 3p$$
Move all \(p\)-terms to the right:
$$4 \;=\; 7p$$
Divide both sides by 7:
$$p^* \;=\; \frac{4}{7}$$
$$p^* = \frac{4}{7} = \frac{\text{number of heads}}{\text{total flips}}$$
Interpretation

This is the Maximum Likelihood Estimate (MLE): the parameter value that makes the observed data most probable.

In general, for \(k\) heads in \(n\) flips:

$$p_{\text{MLE}} = \frac{k}{n}$$

MLE simply says: your best estimate for the probability is the empirical frequency.

Lecture Connection

MLE traces back to Ronald Fisher (1922), as mentioned in Lecture 1: Overview. Nearly every learning algorithm in this course minimizes training loss — which is often the negative log-likelihood. So you just solved the simplest version of what gradient descent does in machine learning!

1e — Computing a Gradient

The core skill for training any machine learning model.

Problem Setup

For \(\mathbf{w} \in \mathbb{R}^d\), constants \(\mathbf{a}_i, \mathbf{b}_j \in \mathbb{R}^d\), and \(\lambda \in \mathbb{R}\):

$$f(\mathbf{w}) = \sum_{i=1}^{n}\sum_{j=1}^{n} (\mathbf{a}_i^\top \mathbf{w} - \mathbf{b}_j^\top \mathbf{w})^2 + \lambda\|\mathbf{w}\|_2^2$$

Compute \(\nabla f(\mathbf{w})\).

Why Gradients Matter

As taught in Lecture 2, to train a model we repeatedly do:

$$\mathbf{w} \leftarrow \mathbf{w} - \eta\,\nabla f(\mathbf{w})$$

If you can't compute the gradient, you can't train the model. So let's master this!

Step-by-Step Solution

Strategy: Simplify → then Differentiate

1

Factor the inner expression.

$$\mathbf{a}_i^\top \mathbf{w} - \mathbf{b}_j^\top \mathbf{w} = (\mathbf{a}_i - \mathbf{b}_j)^\top \mathbf{w}$$
Let \(\mathbf{c}_{ij} = \mathbf{a}_i - \mathbf{b}_j\) for shorthand.
2

Use the key identity (chain rule for squared dot products):

$$\nabla_{\mathbf{w}} (\mathbf{c}^\top \mathbf{w})^2 = 2\,(\mathbf{c}^\top \mathbf{w})\;\mathbf{c}$$

Scalar version: \(\frac{d}{dw}(cw)^2 = 2c^2 w = 2(cw) \cdot c\). Same idea!

3

Apply to the double sum:

$$\nabla_{\mathbf{w}}\sum_{i,j}(\mathbf{c}_{ij}^\top \mathbf{w})^2 = 2\sum_{i=1}^{n}\sum_{j=1}^{n} \big[(\mathbf{a}_i - \mathbf{b}_j)^\top \mathbf{w}\big]\;(\mathbf{a}_i - \mathbf{b}_j)$$
4

Gradient of the regularization term:

$$\nabla_{\mathbf{w}}\;\lambda\|\mathbf{w}\|_2^2 = \nabla_{\mathbf{w}}\;\lambda\sum_{k=1}^{d}w_k^2 = 2\lambda\,\mathbf{w}$$
5

Combine:

$$\nabla f(\mathbf{w}) = 2\sum_{i=1}^{n}\sum_{j=1}^{n}\big[(\mathbf{a}_i - \mathbf{b}_j)^\top \mathbf{w}\big](\mathbf{a}_i - \mathbf{b}_j) \;+\; 2\lambda\,\mathbf{w}$$
Scalar Sanity Check (d = 1)

When everything is a scalar (\(w, a_i, b_j \in \mathbb{R}\)):

$$f(w) = \sum_{i,j}(a_i - b_j)^2 w^2 + \lambda w^2$$
$$f'(w) = 2\sum_{i,j}(a_i - b_j)^2 w + 2\lambda w$$

Matches the vector answer when \(d = 1\). ✅

Lecture Connection

The \(\lambda\|\mathbf{w}\|^2\) term is called regularization. As discussed in Lecture 2 on SVMs, it prevents weights from growing too large — an implementation of Occam's razor (prefer simpler models). You'll see this in nearly every ML assignment in this course.

2a — Counting Possible Faces

How many ways can you place 6 rectangles on an image? A combinatorics warm-up.

Problem Setup

You have an \(n \times n\) pixel image. A "face" consists of 6 axis-aligned rectangles: 2 eyes, 2 ears, 1 nose, 1 mouth. No constraints on location or size. How many possible faces are there?

Give your answer in the form \(O(n^c)\) or \(O(c^n)\).

Intuition

🖼️ The "Picking Edges" Approach

To specify a rectangle on a grid, you need to choose 4 things: where the left edge is, where the right edge is, where the top edge is, and where the bottom edge is.

Think of it like drawing a box: pick two vertical lines and two horizontal lines, and the box is determined.

Step-by-Step Solution
1

Count ways to choose one rectangle.

An axis-aligned rectangle is defined by 4 values:

  • Left column: \(n\) choices (\(1\) to \(n\))
  • Right column: \(n\) choices (must be ≥ left, but for big-O we can ignore this — it's \(O(n)\))
  • Top row: \(n\) choices
  • Bottom row: \(n\) choices
$$\text{Rectangles per image} = O(n) \times O(n) \times O(n) \times O(n) = O(n^4)$$
2

Count the full face. A face has 6 independent rectangles. Each is chosen independently.

$$\text{Faces} = \underbrace{O(n^4)}_{\text{eye 1}} \times \underbrace{O(n^4)}_{\text{eye 2}} \times \underbrace{O(n^4)}_{\text{ear 1}} \times \underbrace{O(n^4)}_{\text{ear 2}} \times \underbrace{O(n^4)}_{\text{nose}} \times \underbrace{O(n^4)}_{\text{mouth}}$$
$$O(n^{4 \times 6}) = O(n^{24})$$
Why This Matters

Even though \(n^{24}\) sounds huge, it's polynomial in \(n\), not exponential. For a \(100 \times 100\) image, that's \(100^{24} = 10^{48}\) — still enormous, but the key insight is:

📐Each rectangle contributes \(O(n^4)\). Each part you add multiplies the exponent by another 4.
🧮If we had \(k\) parts instead of 6: \(O(n^{4k})\).

2b — Minimum Cost Path in a Grid

A classic dynamic programming problem — the backbone of AI search.

Problem Setup

You have an \(n \times n\) grid. Start at \((1,1)\), reach \((n,n)\) by moving only down or right. Each cell \((i,j)\) has cost \(c(i,j)\) which can be negative. Find the path with minimum total cost.

Intuition

🗺️ The "City Blocks" Analogy

Imagine walking through a city grid from the top-left corner to the bottom-right. At each intersection you can only go down or right. Each block has a toll (which could be a reward if negative).

The key insight: to find the cheapest way to reach any intersection, you only need to know the cheapest way to reach the two intersections immediately above and to the left — because those are the only two ways to arrive.

Step-by-Step Solution
1

Define the subproblem. Let \(d(i,j)\) = minimum cost to go from \((1,1)\) to \((i,j)\).

2

Write the recurrence. To reach \((i,j)\), you must come from either above \((i-1,j)\) or left \((i,j-1)\):

$$d(i,j) = c(i,j) + \min\big(d(i-1,j),\; d(i,j-1)\big)$$
3

Handle the base cases.

$$d(1,1) = c(1,1)$$
First row (can only come from the left):
$$d(1,j) = c(1,j) + d(1,j-1) \quad \text{for } j > 1$$
First column (can only come from above):
$$d(i,1) = c(i,1) + d(i-1,1) \quad \text{for } i > 1$$
4

Fill the table. Process row by row, left to right. Each cell takes \(O(1)\) work (one comparison + one addition). There are \(n^2\) cells.

$$\text{Runtime: } O(n^2)$$

Example (3×3):

Col 1Col 2Col 3
Row 1\(c(1,1)\)→→
Row 2↓\(\min(\text{↑, ←}) + c\)→
Row 3↓↓\(d(n,n) = \text{answer}\)
Lecture Connection

This is exactly the type of dynamic programming discussed in the overview lecture. As Prof. Liang explains: DP = recurrence + memoization. The same pattern (define subproblems → write recurrence → fill bottom-up) will appear in the text reconstruction and blackjack assignments.

2c — Ways to Climb a Staircase

A counting problem with a beautiful pattern: powers of 2.

Problem Setup

A staircase has \(n\) steps. You start on the ground and can take any number of steps forward at a time (1, 2, 3, …, up to \(n\)), but you never step backwards. How many ways to reach the top?

Example: \(n = 3\) → answer is 4:

  1. 1 + 1 + 1
  2. 2 + 1
  3. 1 + 2
  4. 3
Intuition

🪜 The "Checkpoint" Analogy

Think of each intermediate step as a checkpoint. For steps 1 through \(n-1\), you have a binary choice: stop here or skip it. You must end on step \(n\).

Since there are \(n-1\) intermediate steps, each with 2 choices:

$$\text{Ways} = \underbrace{2 \times 2 \times \cdots \times 2}_{n-1 \text{ choices}} = 2^{n-1}$$
Step-by-Step Proof
1

Define the recurrence. Let \(f(k)\) = number of ways to reach step \(k\).

To reach step \(k\), you could take your last jump from step 0, 1, 2, …, or \(k-1\):

$$f(k) = f(0) + f(1) + f(2) + \cdots + f(k-1)$$

Base case: \(f(0) = 1\) (one way to be at the ground: do nothing).

2

Compute a few values:

\(k\)\(f(k)\)Calculation
01Base case
11\(f(0) = 1\)
22\(f(0) + f(1) = 1 + 1\)
34\(f(0) + f(1) + f(2) = 1 + 1 + 2\)
48\(f(0) + f(1) + f(2) + f(3) = 1+1+2+4\)

Pattern: \(1, 1, 2, 4, 8, 16, \dots\) → doubles each time!

3

Prove the doubling. Notice:

$$f(n) = f(0) + f(1) + \cdots + f(n-1)$$
$$f(n-1) = f(0) + f(1) + \cdots + f(n-2)$$
Subtract the second from the first:
$$f(n) - f(n-1) = f(n-1)$$
$$f(n) = 2\,f(n-1)$$

Since \(f(1) = 1\), we get:

$$f(n) = 2^{n-1}$$

Sanity checks:

✅\(n = 1\): \(2^0 = 1\). Only one way: take 1 step. ✓
✅\(n = 3\): \(2^2 = 4\). Matches the example. ✓
✅\(n = 4\): \(2^3 = 8\). (Enumerate them to verify!) ✓

2d — Efficient Computation of f(w)

Precompute once, evaluate fast — a classic machine learning trick.

Problem Setup

Recall the function from Problem 1e:

$$f(\mathbf{w}) = \sum_{i=1}^{n}\sum_{j=1}^{n} (\mathbf{a}_i^\top \mathbf{w} - \mathbf{b}_j^\top \mathbf{w})^2 + \lambda\|\mathbf{w}\|_2^2$$

Naively, this takes \(O(n^2 d)\) time to evaluate (\(n^2\) pairs, each dot product costs \(O(d)\)). Goal:

  • Preprocessing: \(O(nd^2)\) time
  • Evaluate \(f(\mathbf{w})\): \(O(d^2)\) time for any given \(\mathbf{w}\)
Key Idea

🧩 Separate what depends on w from what doesn't

The vectors \(\mathbf{a}_i\) and \(\mathbf{b}_j\) are fixed constants. Only \(\mathbf{w}\) changes. If we can gather all the "data stuff" into one precomputed matrix, then evaluating \(f\) for any new \(\mathbf{w}\) becomes cheap.

Step-by-Step Solution
1

Rewrite the function using vectors.

Using \(\mathbf{a}_i^\top \mathbf{w} - \mathbf{b}_j^\top \mathbf{w} = (\mathbf{a}_i - \mathbf{b}_j)^\top \mathbf{w}\), each squared term becomes:

$$\big[(\mathbf{a}_i - \mathbf{b}_j)^\top \mathbf{w}\big]^2 = \mathbf{w}^\top (\mathbf{a}_i - \mathbf{b}_j)(\mathbf{a}_i - \mathbf{b}_j)^\top \mathbf{w}$$
Using the identity: \((\mathbf{c}^\top \mathbf{w})^2 = \mathbf{w}^\top \mathbf{c}\mathbf{c}^\top \mathbf{w}\)
2

Factor out \(\mathbf{w}\). Summing over all \(i,j\):

$$f(\mathbf{w}) = \mathbf{w}^\top \underbrace{\left[\sum_{i=1}^n \sum_{j=1}^n (\mathbf{a}_i - \mathbf{b}_j)(\mathbf{a}_i - \mathbf{b}_j)^\top\right]}_{\mathbf{M} \;(d \times d \text{ matrix})} \mathbf{w} \;+\; \lambda\,\mathbf{w}^\top \mathbf{w}$$

This simplifies to:

$$f(\mathbf{w}) = \mathbf{w}^\top (\mathbf{M} + \lambda \mathbf{I})\, \mathbf{w}$$
3

Expand \(\mathbf{M}\) to make preprocessing efficient.

Naively computing \(\mathbf{M}\) requires \(n^2\) outer products → \(O(n^2 d^2)\). But we can expand:

$$(\mathbf{a}_i - \mathbf{b}_j)(\mathbf{a}_i - \mathbf{b}_j)^\top = \mathbf{a}_i\mathbf{a}_i^\top - \mathbf{a}_i\mathbf{b}_j^\top - \mathbf{b}_j\mathbf{a}_i^\top + \mathbf{b}_j\mathbf{b}_j^\top$$

Sum over \(i\) and \(j\):

$$\mathbf{M} = \;n\sum_{i=1}^n \mathbf{a}_i\mathbf{a}_i^\top \;-\; \left(\sum_{i=1}^n \mathbf{a}_i\right)\!\left(\sum_{j=1}^n \mathbf{b}_j\right)^{\!\top} \;-\; \left(\sum_{j=1}^n \mathbf{b}_j\right)\!\left(\sum_{i=1}^n \mathbf{a}_i\right)^{\!\top} \;+\; n\sum_{j=1}^n \mathbf{b}_j\mathbf{b}_j^\top$$
4

Verify the cost.

OperationCost
\(\sum_i \mathbf{a}_i\mathbf{a}_i^\top\): \(n\) outer products of \(d\)-vectors\(O(nd^2)\)
\(\sum_j \mathbf{b}_j\mathbf{b}_j^\top\): \(n\) outer products\(O(nd^2)\)
\(\sum_i \mathbf{a}_i\) and \(\sum_j \mathbf{b}_j\): sum \(n\) vectors\(O(nd)\)
Outer product of two \(d\)-vectors\(O(d^2)\)
Combine into \(\mathbf{M}\): add \(d \times d\) matrices\(O(d^2)\)

Preprocessing: Compute \(\mathbf{M}\) in \(O(nd^2)\) time ✅

Evaluation: \(f(\mathbf{w}) = \mathbf{w}^\top (\mathbf{M} + \lambda\mathbf{I})\, \mathbf{w}\) in \(O(d^2)\) time ✅

Why \(O(d^2)\)? Computing \(\mathbf{v} = (\mathbf{M} + \lambda\mathbf{I})\mathbf{w}\) is a \(d \times d\) matrix times \(d \times 1\) vector → \(O(d^2)\). Then \(\mathbf{w}^\top \mathbf{v}\) is a dot product → \(O(d)\). Total: \(O(d^2)\).

Lecture Connection

This "precompute the kernel/Gram matrix" trick is ubiquitous in machine learning. By separating the data-dependent part (\(\mathbf{M}\)) from the parameter-dependent part (\(\mathbf{w}\)), you avoid redundant computation during training when \(\mathbf{w}\) changes every iteration but the data stays the same.
