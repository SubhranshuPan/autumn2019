🎯 Background: What is K-Means?

K-Means is an unsupervised learning algorithm. Unlike classification (where we have labels), here we just have data points and want to group them into K clusters — points that are "close together" should be in the same group.

The Three Key Pieces
PieceWhat It IsNotation
Data points The examples we want to cluster $\phi(x_1), \phi(x_2), \ldots, \phi(x_n)$
Cluster centers The "representative point" of each cluster (the average) $\mu_1, \mu_2, \ldots, \mu_K$
Assignments Which cluster each point belongs to $z_i \in \{1, 2, \ldots, K\}$
The Algorithm — Two Steps, Repeated

K-Means alternates between two steps until nothing changes:

Step 1: ASSIGN — For each data point, find which center is closest. Assign the point to that cluster.

$z_i = \arg\min_{j} \|\phi(x_i) - \mu_j\|^2$

Step 2: UPDATE — For each cluster, recompute the center as the average of all points assigned to it.

$\mu_j = \dfrac{1}{|C_j|}\sum_{i \in C_j} \phi(x_i)$

Repeat until assignments don't change (convergence).

The Objective: Reconstruction Loss $$\text{Loss} = \sum_{i=1}^{n} \|\mu_{z_i} - \phi(x_i)\|^2$$

Sum of squared distances from each point to its assigned center. Lower is better.

💡 Plain English intuition

Imagine you're organizing desks in a school. You have K classrooms. You want to assign each student to a room so that students in the same room are "similar." The room's center desk should be right in the middle of all its students.

Step 1: Each student walks to the nearest classroom center. Step 2: Each classroom moves its center desk to be right in the middle of its current students. Repeat until nobody wants to switch rooms.

⚠️ Key observation

The two initializations gave completely different clusterings!

  • Init 1 separated points by vertical position (top vs. bottom)
  • Init 2 separated points by horizontal position (left vs. right)

This shows that K-Means is sensitive to initialization. The algorithm finds a local minimum, but different starting points can lead to different local minima.

💻 Part 4b: Implementing K-Means (Code)

The Algorithm Overview

What the code needs to do
  1. Initialize K centers by picking K random data points
  2. Repeat until convergence (or maxIters):
    • Assign each point to its nearest center
    • Update each center to be the average of its assigned points
  3. Return the centers, assignments, and total reconstruction loss
⚠️ Performance Matters!

Data points are sparse vectors (dicts), but after averaging, centers become dense (many keys). Computing $\|\mu - \phi(x)\|^2$ naively is expensive. The trick is to use this identity:

$\|\mu - \phi(x)\|^2 = \|\mu\|^2 - 2 \cdot \mu \cdot \phi(x) + \|\phi(x)\|^2$

We precompute $\|\mu_j\|^2$ and $\|\phi(x_i)\|^2$ once, then only need the dot product (which is fast due to the sparse $\phi(x)$).

The Complete Code

def kmeans(examples, K, maxIters):
    # Step 1: Initialize centers to K random data points
    centers = [dict(examples[i]) for i in random.sample(range(len(examples)), K)]
    assignments = [0] * len(examples)

    for t in range(maxIters):
        # Precompute ||center_j||^2 for speed
        centerNorms = [dotProduct(c, c) for c in centers]

        # Step 2: ASSIGN each point to its nearest center
        newAssignments = []
        for i, x in enumerate(examples):
            # For each center j, distance = ||c_j||^2 - 2*(c_j · x) + ||x||^2
            # Since ||x||^2 is the same for all j, we can ignore it for argmin
            bestJ = min(range(K), key=lambda j: centerNorms[j] - 2 * dotProduct(centers[j], x))
            newAssignments.append(bestJ)

        # Check for convergence (assignments didn't change)
        if newAssignments == assignments:
            break
        assignments = newAssignments

        # Step 3: UPDATE centers to be the average of assigned points
        for j in range(K):
            clusterPoints = [examples[i] for i in range(len(examples)) if assignments[i] == j]
            if len(clusterPoints) > 0:
                centers[j] = {}
                for x in clusterPoints:
                    increment(centers[j], 1.0, x)
                for f in centers[j]:
                    centers[j][f] /= len(clusterPoints)

    # Compute total reconstruction loss
    totalCost = 0.0
    for i in range(len(examples)):
        # ||center - x||^2 = ||c||^2 - 2*(c·x) + ||x||^2
        totalCost += dotProduct(centers[assignments[i]], centers[assignments[i]]) \
                   - 2 * dotProduct(centers[assignments[i]], examples[i]) \
                   + dotProduct(examples[i], examples[i])

    return centers, assignments, totalCost

Line-by-Line Explanation

Step 1: Initialization 
centers = [dict(examples[i]) for i in random.sample(range(len(examples)), K)]
assignments = [0] * len(examples)
  • random.sample(range(len(examples)), K) — picks K unique random indices
  • dict(examples[i]) — makes a copy of the data point (so we don't modify the original data)
  • assignments = [0] * len(examples) — start all assignments at 0 (we'll update them immediately)
Step 2: The Assignment Step (the speed trick) 
centerNorms = [dotProduct(c, c) for c in centers]

bestJ = min(range(K), key=lambda j: centerNorms[j] - 2 * dotProduct(centers[j], x))

This is the core performance optimization. Instead of computing the full distance:

$\|\mu_j - x\|^2 = \underbrace{\|\mu_j\|^2}_{\text{precomputed}} - 2 \cdot \underbrace{\mu_j \cdot x}_{\text{fast (x is sparse)}} + \underbrace{\|x\|^2}_{\text{same for all j}}$

Since $\|x\|^2$ doesn't depend on $j$, it won't change which $j$ is the minimum. So we drop it!

min(range(K), key=...) finds the index j from 0 to K-1 that minimizes the expression.

Convergence Check 
if newAssignments == assignments:
    break

If nobody changed clusters, we've converged — stop early! No point continuing for the remaining iterations.

Step 3: The Update Step 
for j in range(K):
    clusterPoints = [examples[i] for i in range(len(examples)) if assignments[i] == j]
    if len(clusterPoints) > 0:
        centers[j] = {}
        for x in clusterPoints:
            increment(centers[j], 1.0, x)
        for f in centers[j]:
            centers[j][f] /= len(clusterPoints)
  1. Collect all points assigned to cluster $j$
  2. Reset center to empty: centers[j] = {}
  3. Sum all points using increment(centers[j], 1.0, x) — this does centers[j] += 1.0 * x
  4. Divide each feature by the count to get the average

The if len(clusterPoints) > 0 guard handles the edge case where a cluster becomes empty.

Computing the Total Cost 
totalCost = 0.0
for i in range(len(examples)):
    totalCost += dotProduct(centers[assignments[i]], centers[assignments[i]]) \
               - 2 * dotProduct(centers[assignments[i]], examples[i]) \
               + dotProduct(examples[i], examples[i])

Uses the same expansion trick: $\|\mu - x\|^2 = \|\mu\|^2 - 2\mu \cdot x + \|x\|^2$

This time we include $\|x\|^2$ because we need the actual distance, not just the relative ranking.

🔗 Part 4c: K-Means with Constraints

Sometimes we know in advance that certain points must be in the same cluster. For example, $S = \{(1,5), (2,3), (3,4)\}$ means: "points 2, 3, 4 must be in one cluster and points 1, 5 must be in another."

Key Insight: Group constrained points together

First, use $S$ to build groups of points that must be together. This is like finding connected components in a graph where the edges are the constraint pairs.

Example: $S = \{(2,3), (3,4)\}$
→ Edge 2-3 and edge 3-4 connect into one component: Group A = {2, 3, 4}
→ Point 1 and 5 are unconstrained: Group B = {1}, Group C = {5}

The Modified Algorithm

✨ Constrained K-Means

Preprocessing: Build groups from constraint set $S$. Each group is a set of points that must share the same cluster assignment.

Repeat until convergence:

Step 1: ASSIGN (modified)

For each group $G$ (not individual point), assign all points in the group to the center that minimizes the total distance for the entire group:

$z_G = \arg\min_j \sum_{i \in G} \|\mu_j - \phi(x_i)\|^2$

Step 2: UPDATE (unchanged)

Recompute each center as the average of all its assigned points, exactly as before:

$\mu_j = \dfrac{1}{|C_j|} \sum_{i \in C_j} \phi(x_i)$

💡 Why does this work?

In normal K-Means, each point independently picks its closest center. Here, a whole group must vote together. We find the center that minimizes the combined distance for the group — like a family that must choose one school for all their kids.

The update step stays the same because the formula for the mean doesn't need to know about constraints — it just averages whatever points are in the cluster.

💡 Still an alternating minimization

This still follows the pattern of alternating minimization:

  • Fix centers, optimize assignments (subject to group constraints)
  • Fix assignments, optimize centers (take the mean)

Each step decreases (or maintains) the total reconstruction loss, so the algorithm still converges.

🔄 Part 4d: Why Run Multiple Times?

✅ Answer — Part 4d

K-Means only finds a local minimum — not necessarily the global best clustering. Different random initializations lead to different local minima (as we saw in Part 4a!).

By running K-Means multiple times with different initializations and keeping the result with the lowest reconstruction loss, we are more likely to find a solution close to the global optimum.

💡 Analogy

Think of K-Means as dropping a ball down a hilly landscape. It rolls to the nearest valley (local minimum). If you drop the ball from different starting positions, it might reach a deeper valley. Running multiple times = dropping the ball many times and picking the deepest valley found.

📏 Part 4e: Scaling Dimensions

Case 1: Scaling ALL dimensions by the same factor

✅ YES — Same clusters are guaranteed

If we multiply every data point and centroid by a constant $c$ in all dimensions, then:

$\|c \cdot \mu_j - c \cdot \phi(x_i)\|^2 = c^2 \cdot \|\mu_j - \phi(x_i)\|^2$

Every distance gets multiplied by the same factor $c^2$. Since the factor is constant, the relative ordering of distances doesn't change. If point $i$ was closest to center $j$ before scaling, it's still closest after scaling.

Therefore, the assignment step produces identical results, the update step computes the same averages (scaled by $c$), and the algorithm converges to the same clusters.

Case 2: Scaling ONLY certain dimensions

❌ NO — Clusters may change

Scaling different dimensions by different amounts changes the relative importance of those dimensions, which can flip which center is closest.

Counterexample

Consider 3 points with K=2:

  • $A = [0, 0]$,   $B = [1, 0]$,   $C = [0, 3]$

Without scaling:

  • $d(A, B) = 1^2 + 0^2 = 1$ (A and B are close!)
  • $d(A, C) = 0^2 + 3^2 = 9$

Natural clustering: {A, B} and {C}

Now scale dimension 1 by 10: $A' = [0,0]$, $B' = [10,0]$, $C' = [0,3]$

  • $d(A', B') = 10^2 + 0^2 = 100$ (A and B are now far apart!)
  • $d(A', C') = 0^2 + 3^2 = 9$

Natural clustering: {A, C} and {B} — completely different!

💡 Why this matters in practice

This is why feature normalization is important in machine learning. If one feature (e.g., salary in dollars) has a much larger range than another (e.g., age in years), it dominates the distance calculation and the clustering is biased toward that feature.

🧠 Big Picture Takeaways

1

K-Means is simple but powerful. Just two steps repeated: assign points to nearest center, then update centers to be the average. It always converges because each step reduces (or maintains) the reconstruction loss.

2

Initialization matters a lot. Different starting centers can lead to completely different final clusters. Always run K-Means multiple times and keep the best result.

3

Sparse vector tricks save time. Rather than computing full distances, use the expansion $\|\mu - x\|^2 = \|\mu\|^2 - 2\mu \cdot x + \|x\|^2$ and precompute the squared norms. The dot product with sparse $x$ only touches non-zero entries.

4

Constraints can be incorporated naturally. To force certain points into the same cluster, just group them and assign the entire group together based on total distance to each center.

5

Feature scaling affects clustering. Uniform scaling preserves clusters, but non-uniform scaling changes which dimensions matter most — always normalize your features before clustering!
